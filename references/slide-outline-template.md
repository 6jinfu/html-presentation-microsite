# Slide Outline Template

Use this when the user has content, PRD notes, or a report outline that needs to become a presentation-style HTML deck.

## Automatic mode selection

- Use 6-8 slides when the material is concise, visual-first, or centered on one main idea
- Use 10-15 slides when the material has multiple chapters, proof layers, data sections, roadmap content, or implementation detail
- If reducing the material to 6-8 pages would create overloaded slides, switch to the longer structure automatically

## Recommended structure for 15-page report mode

1. Cover
- One thesis headline
- One 1-2 sentence framing paragraph
- One visual anchor

2. Agenda or map
- 3-5 chapters
- Strong numbering or chapter naming

3. Context or problem framing
- Explain why this topic matters now
- Establish pressure, opportunity, or decision context

4. Core thesis
- One decisive point
- 2-3 support statements

5. Chapter opener or narrative reset
- Short title slide or strong visual divider
- Signals entry into the next chapter

6. Metrics or proof
- 2-4 large stats
- One small chart, comparison, or ranked list

7. Proof detail A
- One deeper supporting point
- One visual, diagram, or comparison

8. Proof detail B
- Another support angle
- Keep it narrower than the thesis slide

9. Visual story
- One dominant image
- 2-4 supporting observations

10. Chapter opener or narrative reset
- Reframe the next section before dense content or showcase content

11. Showcase interaction
- Accordion, reveal, timeline, comparison, or chapter gallery

12. Capability or solution breakdown
- 3-4 modules, pillars, or workstreams

13. Implementation or roadmap
- Milestones, phases, or rollout logic

14. Summary
- 3-4 short takeaways

15. Closing
- Final statement
- CTA, sign-off, or next step

## Compact structure for 8-page showcase mode

1. Cover
2. Agenda
3. Core thesis
4. Metrics or proof
5. Visual story
6. Showcase interaction
7. Summary
8. Closing

## Conversion rules
- Convert long paragraphs into short narrative blocks
- Reduce each slide to one main idea
- Keep titles under roughly 10-12 words when possible
- If the content is dense, split it across more slides rather than overloading one page
- Reserve the most visually dynamic layout for the showcase slide, not the entire deck
- In 10-15 page decks, group slides into chapters so the narrative feels intentional instead of merely longer
- Not every page needs equal visual intensity; use calm slides to support standout slides
- For Chinese decks, decide title line count slide by slide; do not leave major title wrapping to default browser behavior
- If a title must be exactly 1, 2, or 3 lines, mark it explicitly in the working outline before implementation
- If a card contains only short text, shrink the card height instead of preserving empty space for symmetry
- When a slide has one hero card and several support cards, allow the support cards to be shorter if their copy is short
- After implementation, do a visual QA pass specifically for:
  - title overflow
  - title container width mismatches
  - card text bleed
  - empty lower halves in text cards
